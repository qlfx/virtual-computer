# 3. 操作指令到模拟内存的连接

这是项目下一阶段的主要工作：让抽象指令通过明确的执行规则访问模块 1 的模拟内存，并逐步把模块 2 中的变量与输出操作连接进来。

## 已有原型

`prototype/memory_wr.py` 拆分韩语音节，依次解释初声、中声、终声；调用同目录 `virtual_machine.py` 中的内存对象。

| 字母 | 当前操作 |
| --- | --- |
| `ㅏ` | 指针右移 |
| `ㅓ` | 指针左移 |
| `ㄹ` | 写入位 0 |
| `ㅂ` | 写入位 1 |
| 其他字母 | 当前不执行操作 |

```console
python -X utf8 03_instruction_memory_bridge/prototype/memory_wr.py
```

原型使用环形指针，移动越过边缘后取模。当前翻译过程中直接执行动作，返回已执行的命令名。它有局部连接能力，尚未统一项目的内存实现和 quine 执行流程。

## 下一阶段路线

1. 约定内存接口：地址单位、读写宽度、越界规则、初始化与状态查看。
2. 明确抽象指令的操作数与执行效果；把字符解析得到的指令表示保存下来。
3. 将解析与执行分开，让执行器通过统一内存接口产生状态变化。
4. 用短程序验证“源代码 → 指令 → 内存前后状态”，记录每一步。
5. 再决定字符串、变量绑定与输出怎样在模拟内存中表示，尝试把韩语 quine 接入这条路径。

以上是计划。当前原型与两个已完成实验分别保留，不把统一执行器列为已完成成果。
